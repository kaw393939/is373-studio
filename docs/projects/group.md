# Your shared content/ETL project

**Build one small content pipeline together.** ETL means extract an input, transform it and load a useful result. The existing course direction includes information isolation, educational-content publishing or another suitable content task. The detailed final criteria are planned until Canvas posts them.

For example, three permitted documents become a deduplicated, categorized briefing draft that a person reviews. Start with a small fixture set before depending on a live feed.

## Agree one workflow

Write the reader/problem, input/source permission, transformation, output and success check. Compare two approaches, then build one narrow path and a meaningful alternative presentation. Explain missing or invalid input and keep source/provenance visible.

AI generation is optional unless the posted assignment requires it. You can demonstrate ETL without a paid API, vector database, knowledge graph or autonomous publishing. Label synthetic data, simulated clients and unfinished integrations clearly.

## Share the whole process

Every member contributes meaningful, comparable **design, development and QA** work. Give each task an owner and a different reviewer. Integrate early and show actual contribution links rather than a plan alone.

| Work | Example owner | Example reviewer |
| --- | --- | --- |
| Source contract + parser + invalid-input checks | Partner A | Partner B |
| Review flow + output page + task checks | Partner B | Partner A |
| Scope/A/B choice, integration and final walkthrough | Both, with named slices | Another peer/team plus partner cross-review |

This is an example split, not proof of equal effort. Adjust it when tasks differ. Keep one shared record and name each person's actual work. A fictional customer agent can support questions; it cannot substitute for a real teammate or human peer review.
