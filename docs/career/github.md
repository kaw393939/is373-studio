# Make your GitHub useful to a new reader

**Optional professional preparation.** IS373 does not add a new graded portfolio or career reflection through this guide. Use this help to extend your existing portfolio and professional materials; follow Canvas if a separate activity is assigned.

Your portfolio shows the result; GitHub shows the source and how you worked. Link your **own profile**, individual repository and shared group repository. Do not duplicate the group's code just to claim a separate project.

## Short checklist

- [ ] My profile has a clear bio and a working portfolio link, if I have one.
- [ ] The relevant repositories are easy to find, with useful names and descriptions.
- [ ] Each README explains the purpose, setup, current scope and limits.
- [ ] The spec links actual checks, issues/PRs, contributions and AI/starter credit.
- [ ] A classmate can follow the setup; private data and secrets stay out of public code.

Current Studios require your own completed repository, merged to `main`, with SPEC, reviewed LEARNING, actual checks and completed issue/PR evidence. App Studio keeps its per-lesson issue and merged-PR requirements. The template, reference branch or localhost address is not the submission. [Exact current instructions](/projects/studios).

## Two short README examples

These are fictional teaching descriptions. Use only claims your own work supports.

**Individual — content application:** “A course project built from the prepared FastAPI Studio. The README identifies completed lessons, local setup, role checks and the actual revision. It distinguishes local behavior from any later deployed release.”

**Shared — content pipeline:** “A small ETL course project: permitted fixtures become a deduplicated review draft with source links. My slice was parsing and validation; a partner owned the review output. AI generation and live-feed ingestion are not claimed unless implemented and checked.”

## Use it effectively

Keep setup commands accurate for the chosen revision. Link the existing spec instead of copying its whole history. Show a useful decision and test, not a long technology list or commit count. Pin strong work when helpful; a separate profile README is optional.

Ask a peer to find your contribution and run one project from its README. Fix the first missing step and try again. Extend your existing portfolio with these links rather than building another site for this guide.
